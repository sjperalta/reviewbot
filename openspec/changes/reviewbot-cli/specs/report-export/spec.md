## ADDED Requirements

### Requirement: System generates markdown review reports
The system SHALL generate a markdown file containing the complete review results.

#### Scenario: Generate markdown report
- **WHEN** a review completes
- **THEN** the system creates a markdown document with the review summary
- **THEN** findings are grouped by severity level
- **THEN** each finding includes file path, title, description, and suggestion
- **THEN** the report includes architecture notes and security notes sections

### Requirement: Report includes a summary section
The report SHALL begin with a summary section containing PR identifier, risk level, total finding count, and breakdown by severity.

#### Scenario: Report summary section
- **WHEN** generating the report
- **THEN** the summary includes PR number, title, and risk level badge
- **THEN** the summary includes a table with finding counts per severity level

### Requirement: Report uses severity-coded formatting
The report SHALL use markdown formatting to visually indicate finding severity (e.g., colored badges, emoji indicators, or formatting).

#### Scenario: Severity coding
- **WHEN** rendering findings in the report
- **THEN** critical findings SHALL have a prominent marker
- **THEN** high severity findings SHALL use bold with warning indicators
- **THEN** medium severity findings SHALL use standard formatting
- **THEN** low severity findings SHALL use subdued formatting

### Requirement: Report includes file-by-file breakdown
The report SHALL group findings by the file they apply to, with file paths as section headers.

#### Scenario: File grouping
- **WHEN** findings are rendered
- **THEN** findings are grouped under their respective file path headers
- **THEN** files without findings are noted with a brief mention

### Requirement: Report includes missing tests analysis
The report SHALL include a section listing files that appear to be missing corresponding test files.

#### Scenario: Missing tests section
- **WHEN** generating the report
- **THEN** the system compares changed source files against test files
- **THEN** source files without corresponding test changes are listed
- **THEN** the section notes potential test gaps

### Requirement: Report includes architecture notes
The report SHALL include architecture observations generated by the AI review.

#### Scenario: Architecture notes section
- **WHEN** the AI response includes architecture_notes
- **THEN** they are rendered in an "Architecture Notes" section
- **THEN** each note includes the affected area and observation

### Requirement: Report includes security notes
The report SHALL include security-related findings in a dedicated section.

#### Scenario: Security notes section
- **WHEN** the AI response includes security_notes or high/critical findings related to security
- **THEN** they are rendered in a "Security Notes" section
- **THEN** critical security issues are highlighted prominently

### Requirement: Reports are saved to a configurable output directory
The system SHALL save markdown reports to a configurable directory (default `./reviews/`).

#### Scenario: Save report to file
- **WHEN** exporting a report
- **THEN** the system saves the markdown to `<output-dir>/pr-<number>-review.md`
- **THEN** the system prints the output file path
- **THEN** the output directory is created if it doesn't exist
